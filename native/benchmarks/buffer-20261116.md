# 输出缓冲测试（2026-11-16）

用户运行中的进程没有被停止。测试没有打开麦克风或 VB-CABLE；合成输入和设备输出均为零。

## WASAPI 设备节拍对照

在确认没有其他活动音频会话的显示器输出设备上，以共享模式依次运行两轮各 60 秒。每 80 毫秒合成一个块，每 25 块额外推迟 15 毫秒；两个测试采用正式 `PlaybackBuffer` 的临时副本，分别设置 0 和 20 毫秒预缓冲。每轮 6001 个实际输出回调，采样率 48 kHz，生产端溢出均为 0。

| 预缓冲 | 缺样回调次数 | 缺样帧数 | 缺样时长 |
| --- | ---: | ---: | ---: |
| 0 毫秒 | 1 | 480 | 10 毫秒 |
| 20 毫秒 | 0 | 0 | 0 毫秒 |

这是各一轮、构造特定抖动的对照，使用真实输出回调但没有真实输入设备、神经网络推理或个人声样，不能确定用户实际设备缺样的根因，也不能保证其他场景不缺样。测试使用的临时副本只改变了 `PlaybackBuffer` 及相关方法的可见性。

## 确定性测试

`cargo test --locked --manifest-path native/Cargo.toml` 包含正式 `PlaybackBuffer` 的测试：240 毫秒块、构造一次额外 60 毫秒生产延迟时，无预留会缺样 60 毫秒，80 毫秒预留则不缺样，并检查音频顺序。额外等待分别为 20、40、80 毫秒，与三种处理模式对应。更严重的抖动或输入输出设备长期时钟漂移仍可能造成缺样。

`node native/benchmarks/buffer_simulation.js` 运行设备无关离散事件模拟；其假设和局限见脚本注释。它不是实际音频设备或模型推理基准。
